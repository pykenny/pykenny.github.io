Before the Migration

The original was a bit wild -- setting up server that serves blog content with some of the contents like post list and article dynamically rendered as requested.

The project covered from previous work experience, and it ends up with Django as a backend service that manages posts and image assets, and a express service that provides web content and renderings. Plus a website-based editor that allows me to preview.

provided, including:

  • Managing a web service on cloud service provider (AWS)

  • Configuration of web server proxy like Nginx

  • Manage static assets like images, fonts, and favicon

  • Get familiar with frontend assets bundler like webpack and Parcel

And the whole job involves things that gets more complicated than estimated:

  • Design mechanism that enables the editor to renders preview in realtime, interacts with local file system, bundle the post and image into somethings , etc.

Adding additional to markdown parser Twisting code rendering library to support layout, code copying, etc.

Pick the tools

Did not took much time making decision. Blog instead of fancy profile site, so I took a peek on top of Jamstack's list, and chose a blog-oriented builder. It also provides community support on Docker service, because at the time of writing I'm having trouble with building runtime environment and libraries on my MacOS machine (which is also part of the reason why not choosing popular choices like Jekyll).
